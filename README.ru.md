# @nuckty/ext-command-content-external

> **Наполнить корень контента из внешних репозиториев Git — команда `content-external`.**

Командное расширение для [nuckty](https://github.com/nuckty/nuckty). Клонирует или обновляет репозитории Git из глобального `config/external.json` в `external/`. Команда `nuckty build` использует подготовленные файлы и не запускает это расширение автоматически.

Нужен Git в `PATH`; для обновлений также нужен Git LFS, даже если в репозитории нет файлов LFS.

## Что добавляет

Одну команду CLI, регистрируемую через `env.commands`:

```
nuckty content-external [--dry-run]
```

- `--dry-run` — сообщает, что будет клонировано или обновлено, ничего не меняя на диске.

## Как работает

1. Читает `config/external.json` — массив URL репозиториев Git.
2. Для каждого URL выводит имя репозитория (последний сегмент пути без `.git`).
3. Существующий `external/<name>/` обновляется, только если это настроенный репозиторий с чистым рабочим деревом. HTTPS, SSH scp и `ssh://`-адреса одного владельца и репозитория GitHub считаются одним источником; другие хосты и пути — нет. Грязную, чужую или непроверяемую копию команда оставляет без изменений и отказывается её обновлять.
4. `--dry-run` печатает план (`would clone <name>` / `would update <name>`).

## Почему отдельный шаг

Сборка читает Markdown из настроенных уровней контента. Она не делает clone или fetch автоматически; Git также может использоваться для метаданных времени изменения. Работа без сети и воспроизводимость требуют готовых файлов, фиксированных версий инструментов и расширений, которые не обращаются к сети.

Запускайте `npx @nuckty/core content-external` из корня сайта, где пакет установлен и добавлен в `ext`. `--dry-run` использует локальные проверки Git, но не делает fetch, clone или запись.

Команда не принимает имя таргета и читает только общий `config/external.json`. Если файла нет или массив пуст, она успешно завершится без подготовки репозиториев. При отдельных `configDir` согласуйте списки таргетов с общим файлом.
